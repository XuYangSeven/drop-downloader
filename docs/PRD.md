## 一、产品背景：我为什么要做这个工具

作为一个普通的内容消费者，我有一个持续了很多年的习惯：**遇到真正喜欢的视频，会想把它保存下来**——可能是想反复观看学习，可能是想分享给朋友，也可能只是怕哪天作者删除了再也找不到。

但这个朴素的需求，在现实中处处碰壁：

**痛点 1：想保存，平台不让。**
越来越多的平台出于版权和流量考虑，关闭了网页端的下载入口。手机 App 里即便有"缓存"功能，视频也被锁死在应用内部——换设备、换账号、想发朋友，都做不到。所谓"缓存"，本质是租借，不是拥有。

**痛点 2：能下载，水印毁所有。**
借助第三方下载站确实能拿到文件，但大大的平台水印、第三方站点的推广 Logo 盖在画面上，反复观看时非常影响体验，分享给朋友也显得廉价。

**痛点 3：画质没得选。**
很多下载渠道只给单一画质选项，往往还是压缩过的模糊版本。明明博主发布的是 1080p，我拿到手的却是 360p 的糊脸画质。

**痛点 4：命令行工具虽强，但普通人用不了。**
我在 GitHub 上找到了开源界的传奇工具 yt-dlp——它支持 1700+ 视频站点、无水印原画下载，能力上完美解决前三个痛点。但它是纯命令行工具，需要安装 Python、敲命令、记参数，对非技术用户（包括想用这个工具的我自己的朋友）门槛过高。

**于是我做了一个决定：站在巨人的肩膀上，把它改造成普通人也能用的产品。**

## 二、产品定位

### 一句话定位

> **把全网最强开源下载器的命令行能力，封装成"粘贴链接即下载"的网页工具。**

### 核心价值主张

| 用户痛点 | DROP 的回答 |
|---|---|
| 平台不让下载 | 支持 1700+ 站点的公开视频，不依赖平台是否提供下载按钮 |
| 水印影响观看 | 直接拉取原视频流，无任何第三方水印 |
| 画质模糊 | 1080p / 720p / 480p / 360p 自由选择，附文件大小预估 |
| 命令行门槛 | 网页界面 + 自动合并 MP4，手机浏览器也能用 |

### 目标用户

- **核心用户**：有"保存喜欢的视频"习惯的内容消费者（学习党、收藏党、分享党）
- **典型画像**：不想学命令行、怕装乱七八糟软件的普通人——包括我自己的朋友
- **明确不服务**：需要下载 DRM 加密内容、付费会员内容的用户（见"产品边界"）

## 三、用户场景与故事

### 场景 1：通勤路上刷到宝藏教程

> 小 S 在地铁上刷到一个 10 分钟的摄影调色教程，讲得极好，想周末跟着练。但列车进隧道没信号，App 缓存也提示"会员专享"。他复制分享文案，粘贴进 DROP，选了 1080p，视频安静地躺进了相册。

### 场景 2：安利给朋友

> 小 S 把收藏的博主视频集发给同事："这个系列讲得特别清楚。" 同事回复："在哪能看？"以前他要发一堆乱七八糟的带水印链接，现在直接把 DROP 下载的 MP4 原文件发过去，朋友圈画质。

### 场景 3：怕内容消失

> 一个小众博主更新三年突然清空账号。小 S 庆幸自己用 DROP 存下了最喜欢的几期——**互联网会遗忘，本地文件不会。**

## 四、产品设计

### 4.1 产品形态

- **本地版**：macOS 双击启动，浏览器访问 `127.0.0.1:8777`，数据零出户
- **云端版**：Render 部署，手机浏览器随时随地访问（密码保护）

### 4.2 核心功能流程（五状态流）

```
① 粘贴链接 → ② 解析结果 → ③ 下载中 → ④ 完成 → ⑤ 出错兜底
```

**① 输入：粘贴即用**
- 直接粘贴 URL，或 App 分享全文（自动提取链接——这是真实用户反馈驱动的改良：我的第一批用户粘贴的是"标题+链接"混合文案，直接解析失败）
- 保存目录可视化，点击可改，且记住选择

**② 解析结果：先看清楚再决定**
- 视频卡片：封面、标题、作者、时长
- 清晰度档位 1080p~360p，每档附预计文件大小
- 最优画质默认标注"推荐"

**③ 下载中：过程透明可控**
- 实时进度条、当前速度、剩余时间
- 滚动日志（对技术用户是信任感来源）
- 随时可取消

**④ 完成：一键取走**
- 显示完整保存路径 + "打开所在文件夹"
- 云端版增加"保存到本设备"（手机直接存相册）

**⑤ 出错：说人话**
- 原始报错全部中文化映射："该内容需要登录才能访问""该视频为私有视频""链接不受支持"——绝不把 `ERROR: Unable to extract...` 甩给用户

### 4.3 技术方案（产品视角摘要）

- **yt-dlp Python API 直调**（非命令行封装）：拿到原生进度回调，实时进度条才有可能
- **ffmpeg 自动合并**：平台普遍分离视频/音频流，用户无感知地拿到完整 MP4
- **FastAPI + 原生 JS**：不引重型框架，保持轻量可控

### 4.4 设计原则

1. **零学习成本**：没有使用说明，页面即全部
2. **过程可见**：下载不是黑盒，进度/速度/日志全透明
3. **失败友好**：错误是常态（链接失效、需登录），兜底体验决定口碑
4. **本地优先**：默认本地运行数据不出户；上云则密码保护

## 五、产品边界（同样重要）

**DROP 明确不做，也不会做：**

- ❌ DRM 加密内容（Netflix、爱优腾会员剧集等）——版权红线
- ❌ 需要登录/付费才能看的内容（暂不支持，未来 cookies 功能也仅限用户自己的合法账号）
- ❌ 批量/播放列表整包下载（首版明确砍掉，防止工具被滥用为"搬运外挂"）

**使用约束写入产品文案**：仅用于个人学习、备份已公开内容，遵守来源站点服务条款。

## 七、成果验证

- **功能验证**：B 站真实链接三场景（短链 / App 分享全文 / 多 P 视频）端到端实测通过；1080p~360p 四档全部下载成功
- **安全验证**：云端版未登录访问全部拦截（401），密码鉴权生效
- **真实反馈迭代**：两轮真人实测暴露的问题（分享文案解析失败、服务进程被误关）均当天修复
- **交付物**：本地版 + 云端版 + 开源仓库 + 本文档

## 八、写在最后

DROP 不是从零造轮子，而是一次**产品人对开源资产的再设计**：yt-dlp 解决了"能不能"，DROP 解决的是"普通人用不用得了"。整个项目最有价值的不是代码，而是这条路径——

> **自己的真实痛点 → 全球最强开源工具 → 最后一公里的体验封装 → 真实用户验证 → 开源回馈社区。**
